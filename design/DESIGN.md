# Kings (Third World: War of Kings) — дизайн-док сервера v1

Проектируем **свой** сервер с **своей** логикой для клиента `com.fenix.kings`.
Жанр — Travian-подобная военно-экономическая MMO. Названия зданий/юнитов/ресурсов
взяты из реального клиента (`texts/strings.txt` + скрины), числовая модель —
на основе обкатанной Travian-механики (референс-репозитории см. в конце).

> Статус: v1, черновик правил. Формулы — стартовые, потом балансируем.

---

## 1. Ресурсы

| Ресурс | Код | Роль | Здание-добытчик |
|---|---|---|---|
| Дерево | `wood` | строительство, войска | Дровосек → Лесопилка |
| Камень | `stone` | строительство, стены | Каменьщик → Каменоломня |
| Железо | `iron` | войска, апгрейды | Рудник → Шахта |
| Еда | `food` | содержание войск/населения | Огород → Ферма |
| Люди | `people` | лимит населения (не копится, а «вместимость») | Хибара → Усадьба |
| Золото | `gold` | премиум/торговля/ускорения | Рынок/Торговая палата |

- **wood/stone/iron/food** — накапливаются, ограничены вместимостью **Склада**.
- **people** — не ресурс-запас, а **кап населения**: сумма вместимости жилья;
  тратится на найм войск и работников.
- **food** имеет **отрицательный расход**: войска и население едят еду/час; если
  баланс < 0 — голод (штрафы).

## 2. Экономика (тик)

Сервер авторитарный. Состояние замка пересчитывается **лениво** (on-demand) от
`last_update` до `now`, а не таймером на каждого игрока.

**Производство ресурса R (в час):**
```
prod_R(level) = BASE_R * FACTOR^(level-1)
```
Стартовые значения (за час, ур.1) и множитель:
```
BASE_wood = BASE_stone = BASE_iron = 30,  BASE_food = 40
FACTOR = 1.163            # ~ травиановский рост добычи (x2 за ~4-5 ур.)
```
Пример: Лесопилка ур.10 ≈ `30 * 1.163^9 ≈ 116/час`.

**Вместимость склада:**
```
capacity(level) = 800 * 1.28^(level-1)
```
**Кап населения (жильё):**
```
pop_cap(level) = 10 * level         # Хибара/Коттедж/Усадьба суммируются
```

**Ленивый апдейт (псевдокод):**
```
dt = now - castle.last_update              # секунды
for R in [wood, stone, iron, food]:
    gained = prod_R_total * dt/3600
    castle.R = min(castle.R + gained, storage_capacity)
castle.food -= upkeep_total * dt/3600      # войска+население
castle.last_update = now
```

## 3. Здания

Категории: **ресурсные**, **инфраструктура**, **военные**, **наука/особые**.
Цена уровня растёт геометрически; время постройки зависит от **Ратуши**.

**Стоимость постройки уровня L (базовый шаблон):**
```
cost_R(L) = BASE_COST_R * COST_FACTOR^(L-1)      # COST_FACTOR = 1.28
build_time(L) = BASE_TIME * TIME_FACTOR^(L-1) / townhall_speed(townhall_level)
townhall_speed(t) = 1 + 0.05*t                   # Ратуша ускоряет стройку
```

## 5. Бой (Travian-модель)

Атака идёт **отрядом** из замка в замок; расчёт на сервере по прибытии.
```
Atk = Σ unit.atk * count
Def = Σ unit.def_type * count * (1 + fence_bonus + wall_science)
ratio = Atk / (Atk + Def)                 # доля потерь сторон (round-robin по типам)
```
- Потери считаются пропорционально силе (упрощённый Travian «immensity»).
- **Караульная башня** — заранее показывает входящую атаку.
- **Забор/Каменотёс** — множители к обороне/прочности.
- **Тайник** — часть ресурсов не грабится.
- Осадные (из Мастерской) — сносят уровни зданий/стен.

## 8. Связь с клиентом
Клиент `com.fenix.kings` говорит на проприетарном бинарном протоколе
(fenixgl-сериализация, `[тип][varint-len][payload]`, markup экранов, инлайн-PNG).
Между нашей логикой и клиентом — **адаптер протокола** (реверсим из декомпила).
Это единственная неизбежная «с нуля» часть; правила и инфру берём готовыми.
